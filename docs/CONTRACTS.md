# Контракты ClawGym с агентом и оркестратором

Дата: 26 октября 2026 года.

**Статус: этап 0 из `plan.md` не выполнен.** Кода Java-оркестратора при реализации не было. Поэтому все форматы, которые ClawGym отдаёт агенту и принимает от него, — условные. Они вынесены в файлы настроек, чтобы реальные форматы можно было подставить без изменения кода. Пока они не сверены, наблюдения на стенде нельзя переносить на ПРОМ: агент учится в другой обвязке.

Проверено только с `dev/fake-agent`. Он написан по этим же условным форматам, поэтому совпадение с ним ничего не говорит о настоящем Pagurus.

## 1. Запрос к агенту

**Где настраивается:** `agents/*.yaml` → `request`, шаблон тела `templates/a2a-message.json`.

| Что | Сейчас | Статус |
| --- | --- | --- |
| Эндпоинт и метод | `POST ${env:AGENT_URL}` | Условно |
| Тело | JSON-RPC `message/send` с `params.message.parts[0].text`; текст подставляется в `{{text}}` или по `request.textPath` | Условно |
| `x-a2a-sender-id` | `SENDER_PREFIX` + корзина + номер прогона + повторение + случайный хвост; для ручного режима `…manual-<n>-<хвост>` или введённый существующий | Правило — владелец, 15 окт; формат условный |
| `x-task-id` | Один на выполнение кейса (`taskIdScope: execution`) или новый на каждое сообщение (`message`) | Правило привязки — владелец, 15 окт; способ генерации условный |
| Авторизация | Заголовки из файла подключения со ссылками `${env:…}`; в журналах значения маскируются | Условно |
| Реплика оператора | Уходит как есть, без префиксов | Условно |
| Модель агента | `model.switch: none` — задана развёртыванием, выбор недоступен; `request` — значение в теле по `model.path` | Способ переключения на стенде не выяснен (MOD-02) |

**Проверить по коду:**
- полный формат запроса оркестратора к агенту;
- когда создаётся `x-task-id` — на обращение или на сообщение;
- как `x-a2a-sender-id` получается из сведений об операторе;
- какие добавки оркестратор вставляет в реплики;
- ограничения длины, повторы при сбоях.

## 2. Ответ агента

**Где настраивается:** `agents/*.yaml` → `response`.

| Что | Сейчас | Статус |
| --- | --- | --- |
| Тип ответа | Только синхронный. Поток и опрос задачи — ошибка проверки настроек | Условно |
| Реплика | JSONPath `replyPath`, например `$.result.parts[*].text`; несколько значений склеиваются через перевод строки | Условно |
| Статус хода | `statusPath` — сохраняется, на логику не влияет | Условно |
| Ошибка агента | `errorPath`; непустое значение — сбой агента | Условно |
| Использование модели | `usage.inputPath`, `usage.outputPath`, `usage.totalPath`. Если путей нет, токены агента — «нет данных», а не ноль | Условно |
| Таймауты | `TURN_TIMEOUT_MS` на реплику, отдельные — на `/reset`, `/case-capture`, `/skill-curator` | Значения — предложение |

**Проверить по коду:**
- синхронный ли ответ;
- бывают ли промежуточные события;
- есть ли usage;
- как выглядят ошибки и таймауты.

## 7. Подготовка и выгрузка набора скиллов

**Это новый механизм, а не готовый API AEFClaw.** Требование установки выбранного набора (SK-03) появилось 25 октября; по сведениям от 15 октября стартовые скиллы менялись только пересборкой.

Реализованы три адаптера (`agents/*.yaml` → `skills.installer`):

- **`none`.** Установки нет. Прогон допускается только с `skillset: build` (стартовые скиллы сборки, промежуточный режим) или без набора. Так сейчас настроено подключение к стенду.
- **`directory`.** Workspace оператора на общем диске: `root` с `{{senderId}}`. Перед установкой очищаются `skills/learned` и `learning/cases/pending`.
- **`http`.** Предложенный HTTP-контракт; его реализует `dev/fake-agent`. Для стенда нужен такой же или иной API на стороне AEFClaw:

| Метод | Путь | Смысл |
| --- | --- | --- |
| POST | `/workspaces/{sender}/prepare` | Очистить прикладные скиллы и очередь pending-кейсов новой сессии |
| PUT | `/workspaces/{sender}/skills` | Записать файлы набора `{ files: [{ path, content }] }`; пути только внутри `skills/learned/` |
| GET | `/workspaces/{sender}/skills` | Выгрузить текущие прикладные скиллы |
| GET | `/workspaces/{sender}/pending` | Список pending-кейсов: проверка изоляции от чужих свежих уроков |
| GET | `/workspaces/{sender}/file?path=` | Прочитать материал: кейс capture, отчёт curator |

После установки ClawGym сверяет контрольные суммы выгруженных файлов с выбранной версией и проверяет, что pending-кейсов нет. Если что-то не совпало, кейсы не запускаются. Выгрузка выполняется после каждого прохода curator — даже неуспешного, потому что правки могли примениться до ошибки — и в конце прогона.

**Вопросы владельцу:**

- Как исключить общие для оператора pending-кейсы и свежие уроки?
- Входит ли `skills/learned/**` целиком в прикладной набор? Или общие скиллы (`scope: general`) — часть версии агента, и их нужно исключить?

## 8. Материалы обучения

Чтение из S3 (сборщик артефактов из `plan.md`, п. 6.7) не реализовано: для него нужны доступ, путь к workspace (скрипт владельца) и решение, нужен ли S3 при наличии API workspace. ## Правила, принятые реализацией

Это предложения, а не решения владельца. Многие из них показаны в дизайне интерфейса как предложения.

1. **Итоговый успех** — все обязательные проверки действий и все критерии LLM-оценки пройдены. Если проверка действий не пройдена, кейс не пройден независимо от судьи. Если действия верны, а оценки нет или судья дал сбой, — «не оценено». Кейс без критериев оценивается только по действиям.
2. **Проверка действий** засчитывает только фактически выполненный вызов, а не разрешение оператора. Запрещённый инструмент нарушает проверку при любой попытке вызова: в отчёте видно, был ли вызов отклонён. Порядок «A до B» выполнен, если A выполнен раньше первого успешного B или B не выполнялся.
3. **Технический сбой кейса.** Это ошибки агента, оператора, `/reset`, таймауты и остановка. После такого сбоя capture не отправляется, кейс не входит в счётчик curator и не оценивается. Исчерпание лимита ходов, времени или запросов оператора считается завершением по лимиту: кейс оценивается, capture отправляется.
4. **Счётчик curator** — число завершённых нетехническим статусом кейсов после прошлого прохода. Неудачный capture его не уменьшает. Финальный проход выполняется, если `curator.final: true` и счётчик не нулевой. По умолчанию перед curator отправляется `/reset`.
5. **Проверяющая корзина.**
   - Подтверждения разрешаются без вмешательства оператора (`checking.confirmations: approve`); можно отдать их оператору (`operator`).
   - Если оператор пометил реплику как поправку, его переспрашивают один раз. При повторе кейс завершается со статусом «нарушение режима проверки», реплика не отправляется.
6. **Нет заглушки.** В автоматическом режиме агент получает ошибку инструмента, вызов считается неожиданным. В ручном режиме вызов ждёт ответа человека (`UNMATCHED_MODE`).
7. **Выбор заглушки.** Из подходящих побеждает заглушка с большим числом условий `when`, при равенстве — первая в файле. Сначала ищется в кейсе, затем в `contracts/tool-defaults.yaml`.
8. **Новая версия после обучения.**
   - Регистрируется, если набор изменился и линия завершилась без остановки.
   - Если один из проходов curator завершился сбоем, версия помечается как частичная и для прогонов не выбирается.
   - При остановке, отсутствии изменений или режиме стартовых скиллов сборки версия не создаётся, но итоговое состояние сохраняется в материалах.
   - По ручному `/skill-curator` версия не создаётся, только фиксируются изменения: правило не согласовано.
9. **Поправки.** Один урок в кейсе считается один раз; поправки без идентификатора урока считаются каждая. Повторная поправка — урок, который уже поправляли в этой линии обучения. Неизвестный идентификатор урока не выдумывается: он переносится в заметку `lessonNote`.
10. **Оператор и судья** вызываются без памяти между вызовами. Каждый раз передаётся полный контекст кейса и журнала, поэтому контексты разных кейсов не смешиваются. По умолчанию оператор видит результаты инструментов: `operator.seesToolResults` в решении.
11. **Повторения прогона** идут отдельными линиями: у каждой своя сессия агента, рабочая копия набора и новая версия.
12. **Лимит длительности кейса** проверяется между ходами; сам ход ограничен `TURN_TIMEOUT_MS`.
13. **Журнал HTTP-обменов** — по просьбе владельца от 26 октября 2026 года. Сохраняются все запросы к агенту и запросы агента к MCP с привязкой к событиям журнала. Предложения реализации:
    - правила маскирования, перечислены в README;
    - обрезка тел после 256 КБ;
    - хранение запросов MCP без `x-task-id` только в памяти.
14. **GigaChat** — по решениям владельца от 26 октября 2026 года: v1 и v2, настраиваемый адрес, авторизация сертификатом. Сертификат необязателен: с http-адресом внутри Istio ClawGym вызывает модель без него. Предложения реализации:
    - сертификат вместе с http-адресом — ошибка настройки, а не тихий отказ от mTLS;
    - `baseUrl` — корень API без версии, путь метода добавляет провайдер или задаёт `path`;
    - `temperature: 0` отклоняется проверкой файлов, потому что GigaChat требует значение больше 0;
    - срабатывание фильтра (`blacklist` и подобные) считается отказом модели, а не ошибкой формата;
    - каждое соединение открывается заново, без пула: ошибка сертификата не прячется за уже открытым соединением.
15. **Удаление прогонов и сессий** — по просьбе владельца от 26 октября 2026 года. Подтверждение в интерфейсе. Идущие прогоны и активные сессии не удаляются, версии скиллов остаются. Предложения реализации:
    - прогон в очереди тоже не удаляется: сначала его убирают из очереди;
    - у версии скиллов из удалённого прогона ссылка на прогон заменяется пометкой «прогон удалён»;
    - номера удалённых прогонов и сессий повторно не выдаются;
    - архива удалённого нет: удаление необратимо.
