# Шпаргалка

[← Руководство](README.md) · [Кейсы](cases.md) · [Решения](solutions.md) · [Корзины](baskets.md) · **Шпаргалка**

Все поля кейса, решения и корзины на одной странице, сообщения проверки файлов и статусы результата. Подробности и рекомендации — по ссылкам в заголовках.

## Кейс

[`cases/[<папка>/]<id>.yaml`](cases.md) · обязательны `id`, `title`, `topic`

```yaml
id: <id>                              # = имя файла; латиница, цифры, . _ / -
title: <название для людей>
topic: <точная тематика>              # = classifier.categoryName в get_static_attributes_assigned
tags: [<метка>, …]
situation: <что произошло на самом деле>          # оператор и судья
facts: [<факт, который можно сообщить агенту>, …] # оператор и судья
start: { <поле>: <значение> }         # {{start.*}} в шаблоне старта
state: { <ключ>: <значение> }         # начальное состояние; меняют effect
tools:
  <инструмент>:
    - id: <имя заглушки>              # по умолчанию <инструмент>#<n>
      when: { <путь>: <условие> }     # значение | {regex} | {in} | {exists} | {not} | {eq}
      result: { json: <JSON> }        # или { text: … }, или { file: <путь в data/> }
      # error: <текст> | { message: <текст>, code: <код> }
      # sequence: [ <ответ>, … ]      # ответы по очереди, последний повторяется
      delayMs: <0–600000>
      effect: { <путь>: <значение> }
reference:
  procedure: [<шаг>, …]
  answer: <правильный ответ клиенту>
  criteria:
    - { id: <id>, text: <проверяемое утверждение>, lesson: <урок>, hint: <regex для офлайн-демо> }
  actions:
    required:
      - { tool: <инструмент>, before: <инструмент>, args: { … }, text: <формулировка>, lesson: <урок> }
    forbidden:
      - { tool: <инструмент>, args: { … }, text: <формулировка>, lesson: <урок> }
    final: <инструмент>
  lessons:
    - { id: <L-тема-NNN>, rule: <правило> }
  finalClass: close_answer            # close_answer | expertise | request_info | operator_instruction
  tools: [<инструмент>, { tool: <инструмент>, count: <n> }]
  finalText: <эталонный итоговый текст>   # нет — берётся answer
```

## Решение

[`solutions/<кейс>/<имя>.yaml`](solutions.md) · обязательны `case`, `operator.instruction` · идентификатор по умолчанию — `<кейс>/<имя>`

```yaml
case: <id кейса>
title: «<название>»                   # по умолчанию — идентификатор
goal: <что проверяет эксперимент>
operator:
  instruction: <стратегия помощи>
  style: <метка>                      # explain-now | explain-on-ask | minimal | facts-only | своя
  seesToolResults: true               # false — без ответов инструментов
  lessons: [{ id: <id>, rule: <правило> }]
limits: { maxTurns: <1–500>, maxDurationSec: <10–86400>, maxOperatorCalls: <1–1000> }
# id: <явный идентификатор>
```

## Корзина

[`baskets/<id>.yaml`](baskets.md), только корень каталога · обязательны `id`, `title`, `type`, `items`

```yaml
id: <id>                              # короткий, без /: попадёт в x-a2a-sender-id
title: <Обучение · … | Проверка · …>
type: training                        # training | checking
description: <замысел и расписание curator>
curator:                              # только training
  every: <0–1000>                     # 0 — без периодических проходов
  final: true                         # проход в конце неполной пачки
  resetBefore: true                   # по умолчанию true
  # enabled: false                    # выключить проходы, не удаляя блок; явные шаги остаются
checking:                             # только checking
  confirmations: approve              # approve | operator
items:
  - solution: <кейс>/<имя>
    limits: { maxTurns: <n> }
  - curator: true                     # только training
    note: <заметка>
```

**Лимиты кейса** — побеждает более частный уровень: `items[].limits` → `limits` решения → `limits` прогона → 20 ходов, 900 с, 30 запросов оператора.

## Сообщения проверки файлов

`ОШИБКА` останавливает прогон с этим файлом, `внимание` — нет, но обычно означает, что часть оценки не заработает.

### Синтаксис и схема — любой файл

| Сообщение | Уровень | Что делать |
| --- | --- | --- |
| Ошибка YAML: … | ошибка | Исправьте синтаксис в указанной строке. Частые причины — отступы, повтор ключа, `: ` внутри значения без кавычек |
| Ожидался YAML-объект с полями | ошибка | Файл — список или строка, а нужен объект `ключ: значение` |
| Нет обязательного поля «…» | ошибка | Добавьте поле |
| Неизвестное поле «…» — будет проигнорировано | внимание | Опечатка в имени или поле не на своём уровне отступа |
| Ожидался тип … | ошибка | Строка вместо списка, число вместо строки и т. п. |
| Допустимые значения: … | ошибка | Возьмите значение из перечня, например `training` или `checking` |
| Идентификатор может содержать латиницу, цифры и символы . _ / - | ошибка | Уберите кириллицу и пробелы из идентификатора |
| Нужно не меньше 1 элементов | ошибка | Пустой список, например `items: []` |
| Значение должно быть не меньше … / не больше … | ошибка | Значение вне диапазона: `delayMs`, лимиты, `curator.every` |
| Значение не подходит ни под один допустимый вариант | ошибка | Неверная форма значения, например элемент `reference.tools` — не имя и не `{ tool, count }` |
| Падение `npm run validate` с `ReferenceError: Unresolved alias` | — | Значение начинается с `*`, например маска `****2208`: возьмите в кавычки |

### Кейс

| Сообщение | Уровень | Что делать |
| --- | --- | --- |
| Кейс с идентификатором «…» уже есть в … | ошибка | Два файла с одним `id` в разных папках `cases/` — сделайте `id` уникальным |
| Идентификатор «…» не совпадает с именем файла | внимание | Переименуйте файл или поправьте `id` |
| Заглушка без ответа: нужен result, error или sequence | ошибка | Добавьте ответ |
| В одном ответе заданы и result, и error | ошибка | Оставьте одно |
| В result нужно ровно одно из json, text, file | ошибка | Оставьте один вид результата |
| Файл ответа data/… не прочитан | ошибка | Положите файл в `config/data/` или исправьте путь в `result.file` |
| Регулярное выражение не компилируется: … | ошибка | Флаг `u`: дефис в классе символов — последним, `[\w.-]` |
| Инструмента «…» нет в contracts/tools.json — агент его не увидит | внимание | Опечатка в имени инструмента или его нет в контракте |
| Инструмента «…» нет в контракте | внимание | То же — в `actions` |
| Инструмент «…» выключен в контракте (enabled: false): агент не сможет его вызвать, проверка не пройдёт | внимание | Уберите обязательное действие или включите инструмент |
| Итоговое действие «…» отсутствует в контракте | внимание | Исправьте `actions.final` |
| Инструмента «…» из эталона F1 нет в контракте: он всегда будет пропущенным (FN) | внимание | Исправьте `reference.tools` |
| Нет эталонного класса финального действия (reference.finalClass): кейс не войдёт в M1 | внимание | Задайте `finalClass` |
| Нет эталонного набора инструментов (reference.tools): F1 инструментов и M2 для кейса не посчитаются | внимание | Задайте `reference.tools` |
| Урок «…» не описан в reference.lessons | внимание | Добавьте урок в каталог или исправьте ссылку |
| Нет критериев ответа: LLM-оценке нечего проверять | внимание | Добавьте `reference.criteria` — или кейс оценится только по действиям |

### Решение

| Сообщение | Уровень | Что делать |
| --- | --- | --- |
| Кейс «…» не найден в cases/ | ошибка | Исправьте `case` или добавьте кейс |
| Решение с идентификатором «…» уже есть в … | ошибка | Два решения с одним путём или явным `id` |

### Корзина

| Сообщение | Уровень | Что делать |
| --- | --- | --- |
| Решение «…» не найдено в solutions/ | ошибка | Исправьте ссылку; после переноса файла решения идентификатор меняется |
| В корзине нет ни одного решения | ошибка | Добавьте хотя бы один `- solution:` |
| Элемент содержит и solution, и curator | ошибка | Разнесите на два элемента |
| Элемент корзины должен ссылаться на решение (solution) или быть шагом curator | ошибка | Пустой элемент или опечатка в ключе |
| В проверяющей корзине /skill-curator не запускается | ошибка | Уберите блок `curator` или смените `type` на `training` |
| Шаг curator недопустим в проверяющей корзине | ошибка | Уберите `- curator: true` |
| Блок checking действует только в проверяющей корзине | внимание | Уберите блок `checking` из обучающей корзины |
| Корзина с идентификатором «…» уже есть в … | ошибка | Сделайте `id` уникальным |

### Перед запуском прогона

Эти сообщения видны на «Запуске прогона» и в `preview`.

| Сообщение | Уровень | Что делать |
| --- | --- | --- |
| Корзина «…» не найдена в baskets/ | ошибка | Исправьте `basket` в `runs/`; корзина в подкаталоге не загружается |
| Подключение не поддерживает /case-capture, а корзина обучающая | ошибка | Задайте `commands.capture` в подключении агента |
| Подключение не поддерживает /skill-curator, а корзина его запускает | ошибка | Задайте `commands.curator` в подключении агента |
| У кейса нет критериев ответа — LLM-оценка пропускается | внимание | Добавьте критерии, если нужна оценка ответа |
| Повторений …, а агент выдерживает … сессии: часть пойдёт по очереди | внимание | Уменьшите `repetitions` или смиритесь с очередью |

## Статусы

**Итог кейса** — в таблице результата прогона:

| Итог | Когда |
| --- | --- |
| Пройден | Все проверки действий и все критерии пройдены; без критериев — все проверки действий |
| Не пройден | Не пройдена проверка действий или критерий |
| Не оценено | Действия верны, но модель оценки не выбрана или судья дал сбой |
| Технический сбой | Сбой агента, оператора, `/reset`, таймаут, остановка — показывается названием статуса |

**Как закончилось выполнение:**

| Статус | Значение | Оценивается |
| --- | --- | --- |
| Завершён | Выполнен терминальный инструмент или оператор завершил кейс | да |
| Исчерпан лимит ходов / времени / запросов оператора | Сработал лимит | да; в обучении capture отправляется |
| Сбой /reset, Сбой агента, Таймаут агента | Агент не ответил или ответил ошибкой | нет |
| Сбой LLM-оператора, Ошибка формата оператора, Таймаут оператора | Модель оператора не дала решения | нет |
| Нарушение режима проверки | Оператор дважды предложил поправку в проверке | нет |
| Агент занят прерванным запросом | Агент не освободил сессию; линия остановлена | нет |
| Остановлен, Внутренняя ошибка стенда | Прогон остановили или упал стенд | нет |

## Команды

| Что | Как |
| --- | --- |
| Собрать проект | `npm run build` |
| Проверить все файлы | `npm run validate` |
| План прогона без запуска | `node dist/src/cli.js preview <настройка>` |
| Запуск без интерфейса | `node dist/src/cli.js run <настройка>` |
| Перечитать файлы в работающем стенде | «Перечитать файлы» на «Кейсах и решениях», «Проверить файлы снова» на «Запуске прогона» или `POST /api/config/reload` |
| Офлайн-демо | `npm run demo`, затем http://127.0.0.1:8080 |
